## 新增「安装 Mod」标签页

- 新增 `_mods_page.py`（`ModsPageMixin`），混入 `ES3Editor` 基类，提供：
  - BepInEx 加载器检测（判断 `BepInEx/core/*.dll` 与 `winhttp.dll`/`version.dll` 注入文件），
    识别 Unity 运行时（Mono / IL2CPP，依据 `*_Data/Managed` 与 `*_Data/il2cpp`）。
  - 一键安装加载器：先请求 GitHub API `repos/BepInEx/BepInEx/releases/latest`
    取 `BepInEx_win_x64_*.zip`，失败回落固定版本 v5.4.23.5；也支持选择本地 zip 安装。
  - 本地安装：支持 zip（BepInEx 完整包 → 解压进游戏根目录；`plugins/` 布局或单目录包裹 → 放进
    `BepInEx\plugins`）与单个 dll。
  - 在线清单：`mods/manifest_url` 可填远程 URL 或本地 json，表格列出后批量下载安装，
    并按已装文件名粗略标记「已安装 / 可安装」。
  - 已装 Mod 管理：启用/禁用（移入 `BepInEx\plugins\disabled`）、卸载（列完整路径二次确认）。
- 游戏目录读取 `mods/game_dir`，缺省回退到地图页的 `map/game_data_dir` 的上一层。
- 新增示例清单 `mods_index.json`；`.gitignore` 对 `*.json` 加了 `!mods_index.json` 例外，
  否则示例清单无法入库。

## 约定与坑

- 新增页面的三处必须对齐，否则导航索引与 stack 页索引会错位：
  1. `self.nav_items` 列表项 `(图标, 文字, key)`；
  2. 页面容器（如 `self.tab_mods`）；
  3. `build_ui()` 里 `self.stack.addWidget()` 的遍历顺序与 `build_xxx_tab()` 调用。
  本次把 mods 追加到末尾（导航 key 与 stack 均 22 位），避免影响既有索引。
- 解压必须防 zip-slip：`_safe_join()` 要求目标落在根目录内，否则中止。
- mod 分发的「单目录包裹」兜底规则必须要求包内含有 .dll，否则普通压缩包会被误装进 plugins。
- 本机（沙箱）环境默认没装 PySide6 / UnityPy；官方源极慢，用阿里云镜像
  `https://mirrors.aliyun.com/pypi/simple/` 可正常安装；清华源上没有 PySide6-Essentials。
- GitHub release 的 CDN 直链在本环境被代理拦截（502），跑真实下载验证时改用本地 http 服务。

## 修复「游戏目录定位用不了」

用户反馈 Mod 页定位用不了。排查结论：**不是 QSettings 失效**（主题记忆一直在用同一套，实测读写正常），
而是定位能力缺失 + 手动归位太脆弱：

- 原来只有手动「选择…」，没有任何自动定位，用户不知道该选哪一层 → 表现为"用不了"。
- 手动选时只向上找一级，选 `*_Data\Managed` 这类子目录必然报"目录不正确"。

修复：
- 新增「自动查找」按钮 + `_detect_game_roots()`：优先级 运行中游戏进程反查（`QueryFullProcessImageNameW`
  拿 exe 路径）> Steam 库（注册表 InstallPath + `libraryfolders.vdf` 正则解析，兼容新旧格式）
  > Epic 与常见安装位置；用 `GAME_NAME_HINTS` 关键词校验，避免把 Steam 库里别的 Unity 游戏认成目标。
- 找到 1 个直接采用，多个弹 `QInputDialog` 选择，0 个提示手动指定。
- 新增 `_coerce_game_root()`：向上逐级（最多 5 层）找 `*_Data` 标记，选根目录 / `*_Data` /
  `*_Data` 下的任意子目录都能归位；失败提示里写清期望目录结构。
- 定位扫描走 `_CallWorker` 后台线程，不卡 UI。

测试：`tests/test_mods.py` 新增 `ModLocateTests`（7 项），全量 96 项通过。
注意 QThread 信号靠主线程事件循环投递，测试里 `wait()` 不够，要 `app.processEvents()` 轮询。
